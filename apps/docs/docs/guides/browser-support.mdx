---
title: Browser support
description: Which browsers run the animation, what happens without it, what has been checked, and what has not.
---

The animation needs `document.startViewTransition`. Without it the theme still changes, instantly. The theme logic itself uses `matchMedia`, and in standalone mode `localStorage` and the `storage` event.

:::warning
The "needs" column comes from [MDN browser compatibility data](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition#browser_compatibility), not from our tests. A browser counts as checked only where the last column says what was run.
:::

| Browser  | startViewTransition | Behavior without it | Checked on                                                                                                                               |
| -------- | ------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Chromium | 111 (MDN)           | Instant switch      | Chromium 159 (Playwright, Linux and macOS, headless and headed), 2026-11-17: animation, navigation guard, reduced motion, rapid toggling |
| WebKit   | 18 (MDN)            | Instant switch      | WebKit (Playwright's current build), 2026-11-17: animation, navigation guard, Nuxt UI components                                         |
| Firefox  | 144 (MDN)           | Instant switch      | Firefox (Playwright's current build), 2026-11-17: has no View Transitions API there, and the instant fallback works                      |
| Edge     | 111 (MDN)           | Instant switch      | unverified                                                                                                                               |
| Safari   | 18 (MDN)            | Instant switch      | unverified (WebKit in Playwright is not the same as Safari)                                                                              |
| Others   |                     |                     | unverified                                                                                                                               |

Firefox in the test environment does not have the API, so the theme switches instantly there. That fallback was checked. Whether a newer Firefox with the API behaves the same has not been checked.

## What was checked

- With `@nuxtjs/color-mode`, `mode: 'color-mode'` animates changes to `preference`, including direct writes from Nuxt UI's `UColorModeButton`, `UColorModeSwitch` and `UColorModeSelect`. Checked in Chromium and WebKit.
- A theme transition does not run during a page navigation. Checked in Chromium and WebKit with `experimental.viewTransition`.
- Reduced motion gives an instant switch.
- A second toggle during a running transition skips the first and ends on the latest theme.
- No flash on reload with cookie storage.

## Real GPU Chrome

All Chromium runs used Playwright's build. Rapid toggling in a Chrome with a real GPU has not been tried. The crash that led to the cancel-first rule showed up in headless Chromium 159, and the rule is in `penumbra-core`.

## Compatibility

The module declares `nuxt: '>=3.12.0'`. The packed tarball was installed into a fresh project for each Nuxt version below, built in each render mode, opened in Chromium and toggled, and the choice was checked after a reload. Last run: 2026-11-25. CI repeats the run on every push.

| Nuxt                        | Server rendering | `ssr: false` | `nuxt generate` | color-mode `localStorage` + SSR |
| --------------------------- | ---------------- | ------------ | --------------- | ------------------------------- |
| 3.12.4 (the declared floor) | checked          | checked      | checked         | checked                         |
| 3.21.11                     | checked          | checked      | checked         | checked                         |
| 4.7.0                       | checked          | checked      | checked         | checked                         |

Each render mode was run in color-mode mode (cookie storage) and in standalone mode. In standalone mode the stored theme was on `<html>` before the first paint in every build, and in every build the switch started a view transition. These have not been run:

- Nuxt versions between the ones in the table
- Safari, Edge, and Firefox with the API
- Browser versions other than the ones in the table above

:::note
A fresh install of Nuxt 3.12 resolves a newer `unstorage` that Nuxt 3.12 itself cannot render with. A bare Nuxt 3.12.4 project fails the same way without this module. The 3.12 run pins `unstorage@1.15.0`; pin it too if you stay on 3.12.
:::

## Feature detection

The module tests `typeof document.startViewTransition === 'function'` on every change. You do not need your own check. If you want to show something different when animation is unavailable:

```ts
const canAnimate = typeof document.startViewTransition === 'function'
```

## Other reasons for no animation

Reduced motion, a zero duration, an unknown effect name and an active navigation also give an instant switch. They are listed under [transitions](/guides/transitions#when-it-switches-instantly).
